# 面向越南留学生的铁道专业汉越术语翻译学习软件 V1.0 软件设计说明书

## 一、引言

### 1.1 编写目的

本文档用于说明“面向越南留学生的铁道专业汉越术语翻译学习软件 V1.0”的需求、总体架构、功能模块、数据结构、接口设计、运行部署、安全权限和测试验证情况。系统采用 H5 前端、Node.js 后端和 MySQL 数据库实现，面向越南留学生提供铁道专业术语的中文、英文、越南语学习、查询、练习和分析能力，同时为教师与管理员提供术语管理、用户管理、日志审计和数据分析后台。

### 1.2 适用对象

本文档适用于软件著作权登记材料编写、项目验收、系统运维交接和后续版本迭代。阅读对象包括项目管理人员、开发人员、测试人员、运维人员、教师管理员和软著材料审核人员。

### 1.3 术语说明

| 术语 | 含义 |
|---|---|
| H5 | 基于浏览器运行的移动端或响应式 Web 前端页面 |
| 术语 | 铁道专业领域的中文词条及其英文、越南语翻译和释义 |
| 练习 | 基于术语数据生成的单选、判断、填空、翻译等答题训练 |
| 错题本 | 记录学生答错术语并支持后续复习的数据集合 |
| 管理台 | 面向教师和管理员的横屏后台管理页面 |

## 二、需求分析

### 2.1 用户认证需求

系统应提供统一登录入口，支持学生、教师、管理员通过账号密码登录。登录成功后系统根据角色展示可访问的业务菜单，并记录登录日志。该需求对应登录页面、认证接口、用户表、角色表和登录日志表。

### 2.2 国际化需求

系统应支持中文、英文和越南语三种界面语言。界面导航、按钮、标题和提示信息由前端国际化资源控制，术语正文、释义和例句由数据库多语言字段控制。该需求对应 H5 学习看板三语言截图、术语表多语言字段和前端语言切换控件。

### 2.3 专业术语管理需求

教师和管理员应能够新增、编辑、删除、查询、筛选和分页查看铁道专业术语。术语需包含中文、英文、越南语、拼音、分类、难度、释义、例句和状态。该需求对应术语管理页面、分类表、术语表和术语管理接口。

### 2.4 练习平台需求

学生应能够选择题型、分类、难度和题目数量后开始练习。系统应支持单选题、判断题、填空题和翻译题，提交后自动判分并生成练习记录。该需求对应练习配置页面、各题型答题页面、练习记录表和答题明细表。

### 2.5 错题与数据分析需求

系统应根据学生答题情况记录错题，统计练习次数、正确率、平均得分、趋势数据和高频错误术语。学生端展示个人学习分析，管理端展示整体数据分析。该需求对应数据分析页面、错题表、练习记录表和分析接口。

### 2.6 公共系统管理需求

系统应提供用户管理、角色查看、登录日志和操作日志查询能力，并支持分页显示。该需求对应系统管理页面、用户表、角色表、登录日志表和操作日志表。

## 三、系统概述

### 3.1 总体说明

系统由 H5 前端、Node.js 后端服务和 MySQL 数据库组成。前端负责页面展示、三语言切换、表单交互、练习答题和数据展示；后端负责认证鉴权、业务接口、练习判分、分页查询和数据持久化；数据库负责存储用户、角色、术语、分类、练习记录、答题明细、错题、收藏和日志数据。

### 3.2 功能模块结构

| 模块 | 服务角色 | 主要页面 | 主要数据对象 |
|---|---|---|---|
| 登录认证 | 学生、教师、管理员 | 登录页 | sys_user、sys_role、sys_login_log |
| 术语管理 | 教师、管理员 | 术语列表、新增弹窗、编辑弹窗 | term_category、railway_term |
| 练习平台 | 学生 | 练习配置、答题页、结果页 | railway_term、practice_record、practice_answer |
| 错题本 | 学生 | 数据分析与错题本 | wrong_question、railway_term |
| 数据分析 | 学生、教师、管理员 | 学习看板、数据分析页 | practice_record、practice_answer、wrong_question |
| 系统管理 | 教师、管理员 | 用户列表、角色、日志 | sys_user、sys_role、sys_login_log、sys_operation_log |

## 四、总体设计

### 4.1 技术架构

系统采用浏览器/服务器架构。前端使用 Vue3 和 Vite 构建 H5 响应式页面；后端使用 Express 提供 REST API；数据库使用 MySQL，字符集采用 utf8mb4 以支持中文、英文和越南语字符。前端通过 HTTP 请求访问后端接口，后端通过连接池访问数据库。部署时数据库地址、端口、账号、密码等敏感配置通过环境变量提供，文档中统一脱敏为 `***`。

### 4.2 前后端交互

用户登录后，后端返回访问凭证，前端将其保存到本地存储并在后续请求中放入请求头。术语管理、练习、分析和系统管理接口均通过鉴权中间件识别用户身份。教师和管理员可访问管理功能，学生主要访问学习与练习功能。

### 4.3 分页设计

术语、分类、用户、角色、登录日志、操作日志、练习记录和错题列表均支持分页查询。分页接口统一接收 `page` 和 `pageSize` 参数，返回 `rows`、`total`、`page`、`pageSize` 四个字段。前端根据总数计算页数，并展示上一页、下一页和总记录数。

## 五、详细设计

### 5.1 登录与角色权限设计

登录页面支持账号密码输入和三语言切换。后端校验用户状态和密码，校验成功后签发访问凭证。用户角色分为管理员、教师和学生。管理员拥有用户管理、术语管理、系统日志和数据分析能力；教师拥有术语维护、学习数据查看和日志查看能力；学生拥有术语学习、练习和个人分析能力。

### 5.2 术语管理设计

术语管理台采用横屏表格布局，主要字段包括中文术语、越南语翻译、英文翻译、分类、难度和操作。管理人员可通过关键词查询定位术语，也可按分类、难度筛选数据。新增和编辑采用弹窗形式，减少页面跳转，保证管理人员在当前列表上下文中完成录入和维护。

### 5.3 练习平台设计

练习平台允许学生选择题型、分类、难度和题目数量。系统从启用状态的术语中筛选数据并随机生成题目。单选题用于识别中文术语对应的越南语翻译；判断题用于判断术语翻译是否匹配；填空题用于输入越南语翻译；翻译题用于将越南语术语翻译为中文术语。提交后系统比较用户答案与正确答案，生成练习记录和答题明细，错误项写入错题表。

<figure class="diagram"><img src="../assets/diagrams/practice_flow.svg" alt="练习业务流程图"><figcaption>图4 练习业务流程图</figcaption></figure>

图4展示学生练习业务的完整处理流程。学生登录后进入练习平台，选择题型、分类、难度和题目数量；后端根据条件查询启用术语并生成单选、判断、填空或翻译题；学生提交答案后，后端逐题比对正确答案，写入练习记录和答题明细，错误项进入错题表；最终结果返回前端并供数据分析模块汇总。该图放在详细设计章节，用于说明练习平台如何把术语库、答题过程、错题本和学习分析连接为闭环。

### 5.4 数据分析设计

学生端分析以个人学习结果为核心，统计练习次数、答题数量、正确数量、平均分、正确率、趋势和错题列表。管理端分析以整体运营数据为核心，统计用户总数、术语总数、练习总次数、平均得分、高频错误术语和分类术语数量。

### 5.5 系统管理设计

系统管理模块展示用户列表、角色信息和登录日志。用户列表用于查看账号、姓名、角色和状态；角色信息用于区分系统权限；登录日志用于审计用户访问情况。列表采用分页方式展示，避免日志和用户数量增加后影响页面性能。

## 八、运行与部署设计

系统运行时需要 Node.js、浏览器和 MySQL 数据库。前端开发服务默认通过 Vite 启动，后端服务通过 Node.js 启动。数据库连接信息通过环境变量配置，文档中不记录真实密码、真实服务器地址或令牌。部署时应先启动数据库，再启动后端服务，最后启动或发布前端资源。后端服务启动时会检查数据库和数据表，确保核心表结构存在。

## 九、安全与权限设计

系统使用密码摘要存储用户密码，避免明文保存。登录成功后使用访问凭证标识用户身份，后端接口通过鉴权中间件保护。管理类接口限制管理员和教师访问，学生角色不能进入用户管理和术语维护操作。系统记录登录日志和操作日志，便于后续审计。涉及数据库地址、账号、密码和运行路径的信息均按软著材料要求脱敏。
